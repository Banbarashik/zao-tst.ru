# Реализация `/regions/[region]`

Пакет собран на основе `regions.xlsx`, существующего `src/data/products.json` и страницы Барнаула.

## Что внутри

- `src/app/regions/[region]/page.tsx` — универсальная динамическая страница.
- `src/data/regions/types.ts` — TypeScript-типы.
- `src/data/regions/regions.generated.ts` — уже сгенерированные данные из текущего Excel.
- `src/data/regions/regions.ts` — финальные объекты с подключёнными транспортными терминалами.
- `src/data/regions/product-map.ts` — сопоставление обозначений из Excel с product-id/категориями.
- `src/data/regions/product-catalog.ts` — читает `src/data/products.json` и строит runtime-набор допустимых `id`.
- `src/data/regions/region-meta.ts` — столицы, aliases и географические исключения.
- `src/data/regions/transport-companies.ts` — транспортные терминалы, извлечённые из `regions.docx` для столиц и городов-анкоров.
- `scripts/generate-regions.ts` — повторная генерация `regions.generated.ts`.
- `source/` — текущие исходные файлы (`regions.xlsx`, `regions.docx`). `products.json` остаётся вашим основным каталогом в `src/data/products.json` и не дублируется в этом пакете.
- `transport-generation-report.json` — отчёт о том, какие города получили/не получили транспортные терминалы.


## Источник product ID

Отдельный `product-ids.generated.ts` больше не используется. Региональный код импортирует существующий `src/data/products.json` и строит набор допустимых ID напрямую из свойства `id` каждого товара:

```ts
import productsJson from "../products.json";

export const PRODUCT_ID_SET = new Set(
  productsJson.map((product) => product.id),
);
```

Таким образом, `products.json` является единственным источником правды для product ID. Если файл лежит не в `src/data/products.json`, достаточно изменить один import в `src/data/regions/product-catalog.ts`.

## Правило секций

1. `h1` — столица субъекта.
2. Любой другой **город**, встречающийся в 4+ строках поставок, получает отдельный `h2` и anchor.
3. Все остальные населённые пункты попадают в финальный `h3` субъекта.
4. Anchor субъекта — транслитерированный `subject.slug`.

Например:

- `/regions/barnaul`
- `/regions/barnaul#biysk`
- `/regions/barnaul#altayskiy-kray`

## Правило отображения продукции

`ProductList` добавляет название товарной категории только при её первом появлении у компании.

Поддерживаемые подписи:

- КСк / КПСк / ТВВ / КП / КФБ / КПВС / КПВУ / КППС / КППУ → `калорифер` / `калориферы`;
- АО 2 / СТД-300 / АВО → `агрегат` / `агрегаты`;
- СФОЦ → `установка` / `установки`;
- ШУК → `шкаф` / `шкафы`;
- СФО → `электрокалорифер` / `электрокалориферы`.

Единственное или множественное число определяется **только первой непрерывной группой этой категории**. Если при первом появлении подряд идут 2+ товара категории, используется множественное число; если один — единственное. При повторном появлении этой категории подпись больше не выводится. Для остальных товаров (например, ТЭНов) дополнительная подпись не добавляется.

Примеры:

- `Калориферы ТВВ 406, ТВВ 407`
- `Агрегат СТД-300 (КСк3), калорифер ТВВ 412`
- `Калориферы КПСк 4-10, КСк 3-5, агрегат СТД-300 (ТВВ4), ТВВ 309, ТВВ 311, ТВВ 410`
- `Установки СФОЦ, СФОЦ-250, СФОЦ-40, СФОЦ-100, шкафы ШУК, ШУК-250`
- `Электрокалориферы СФО, СФО-40, шкафы ШУК, ШУК-40`


## Транспортные компании

`RegionData.transportTerminals` хранится как словарь по slug населённого пункта:

```ts
transportTerminals: {
  barnaul: [
    { company: "ПЭК", address: "...", deliveryTime: { minDays: 3 } },
    { company: "Деловые Линии", address: "...", deliveryTime: { minDays: 3 } },
  ],
  biysk: [
    { company: "ПЭК", address: "...", deliveryTime: { minDays: 4 } },
    { company: "Деловые Линии", address: "...", deliveryTime: { minDays: 3 } },
  ],
}
```

Правила переноса из DOCX:

1. Используются только столица страницы и города, которые уже стали отдельными anchor-секциями по правилу `4+` поставок.
2. Колонки `1/2/3 УРОВЕНЬ` не влияют на структуру страницы.
3. Первый адрес города в DOCX считается терминалом `ПЭК`, второй — `Деловые Линии`.
4. Если для нужного города нельзя уверенно определить **оба** адреса, транспортные данные для этого города не добавляются.
5. Адрес сохраняется как в DOCX, только переносы строк/лишние пробелы сведены к обычным пробелам.
6. Срок вида `3 дня` преобразуется в `deliveryTime: { minDays: 3 }`.
7. Терминалы выводятся после списка предприятий столицы и после списка предприятий каждого anchor-города. В финальной секции субъекта терминалы не выводятся.

По текущему `regions.docx` сформированы данные для **74 населённых пунктов** в **65 региональных страницах** — всего **148 терминалов**. Подробности и пропуски есть в `transport-generation-report.json`.

## Повторная генерация после обновления Excel

Установить dev-зависимости:

```bash
npm i -D exceljs tsx
```

Запустить:

```bash
npx tsx scripts/generate-regions.ts
```

Если проект использует `src/`, структура готова как есть. Если `app/` и `data/` лежат в корне проекта, перенеси содержимое `src/` на соответствующий уровень.

## Важные допущения

- `Московская область` использует страницу `/regions/moskva`, потому что в исходных данных Москва является основным центральным городом.
- `Ленинградская область` использует `/regions/sankt-peterburg`.
- `г. Донецк` нормализован в `Донецкая Народная Республика` / `Донецк`.
- `Мелитополь` нормализован в `Запорожская область` / `Мелитополь`.
- `Республика Саха` объединяется с `Республика Саха (Якутия)`.
- `Чувашская республика` объединяется с `Чувашская Республика`.
- `Крым` нормализован в `Республика Крым`.
- `Орел` нормализован в `Орёл`.
- Для четырёх субъектов в Excel нет строк поставок по выбранной столице: Карачаево-Черкесская Республика, Ставропольский край, ХМАО-Югра, Ямало-Ненецкий АО. Страница всё равно создаётся по столице; столичный список на ней будет пустым.
