# Памятка: как привязываются транспортные терминалы к страницам регионов

## Главное правило

Во внутреннем объекте `TRANSPORT_TERMINALS[regionSlug]` ключ — это **не город, в котором физически находится терминал**.

Ключ должен быть равен `settlement.slug` того населённого пункта, **под поставками которого терминалы должны выводиться на странице**.

Пример:

```ts
salekhard: {
  "tarko-sale": [
    {
      company: "Деловые Линии",
      address: "г. Новый Уренгой, ...",
      deliveryTime: { minDays: 10 },
    },
    {
      company: "ПЭК",
      address: "г. Новый Уренгой, ...",
      deliveryTime: { minDays: 9 },
    },
  ],
},
```

Терминалы физически находятся в Новом Уренгое, но если они обслуживают поставки в Тарко-Сале, ключом должен быть `tarko-sale`.

## Почему так работает

На `/regions/[region]` терминалы не выводятся просто потому, что они есть в `transport-companies.ts`.

Для финальной секции региона (`h3`) страница сначала собирает slug населённых пунктов из поставок:

```ts
const settlementSlugs = [
  ...new Set(companies.map((company) => company.settlement.slug)),
];

return settlementSlugs.flatMap(
  (settlementSlug) => transportTerminals[settlementSlug] ?? [],
);
```

Поэтому объект

```ts
salekhard: {
  "novy-urengoy": [...]
}
```

не будет показан, если в `regions.generated.ts` нет компании с:

```ts
company.settlement.slug === "novy-urengoy"
```

Даже если фактический адрес терминала находится в Новом Уренгое.

## Где какие ключи используются

### Столица региона (`h1`)

Используется:

```ts
region.transportTerminals[region.capital.slug]
```

Поэтому терминалы под столицей:

```ts
salekhard: {
  salekhard: [...]
}
```

### Отдельный anchor-город (`h2`)

Используется:

```ts
region.transportTerminals[settlement.slug]
```

Ключ должен совпадать со slug этого города.

### Финальная секция региона (`h3`)

Используются только slug населённых пунктов, реально присутствующих в `remainderCompanies`.

Ключ должен совпасть с `company.settlement.slug` одной из компаний этой секции.

## Пример: Ямало-Ненецкий АО

Адреса терминалов:

```text
г. Новый Уренгой, ул. Таежная, 224/1
г. Новый Уренгой, ул. Имени В. Я. Петуха, д. 17
```

не означают, что внутренний ключ должен быть `novy-urengoy`.

Нужно сначала определить, **под поставками в какой населённый пункт** эти терминалы должны выводиться.

Если под Салехардом:

```ts
salekhard: {
  salekhard: [...]
}
```

Если под Тарко-Сале:

```ts
salekhard: {
  "tarko-sale": [...]
}
```

Если в данных поставок появится Новый Уренгой:

```ts
salekhard: {
  "novy-urengoy": [...]
}
```

## Важно про slug Нового Уренгоя

Текущая `slugifyRussian()` даёт:

```text
Новый Уренгой -> novy-urengoy
```

а не:

```text
noviy-urengoy
```

То есть `noviy-urengoy` не соответствует проектной системе slug.

Но даже правильный `novy-urengoy` не будет выведен, если Новый Уренгой отсутствует среди населённых пунктов поставок этой страницы.

## Быстрая памятка

Перед добавлением терминалов:

1. Определить региональную страницу.
2. Определить, **под поставками какого населённого пункта** должны стоять терминалы.
3. Найти `settlement.slug` этого места в `regions.generated.ts`.
4. Использовать именно этот slug как внутренний ключ.
5. Не брать slug автоматически из физического адреса терминала.

Формула:

```text
внешний ключ = slug региональной страницы
внутренний ключ = settlement.slug места поставки
address = физический адрес транспортного терминала
```

Эти три сущности могут не совпадать.
