# aria-label для взаимных ссылок «регион ↔ товар»

## Готовые файлы

### 1. `data/regions/product-link-aria.ts`

Общий генератор aria-label:

- региональная страница → товар / категория;
- товарная страница → кликабельный город.

### 2. `data/regions/city-name-forms.ts`

Родительный падеж городов для конструкции:

`на предприятиях города Омска`

Словарь включает текущие столицы и anchor-города, используемые архитектурой
`product-deliveries.generated.ts`.

### 3. `app/regions/[region]/page.tsx`

Актуальная региональная страница уже изменена.

Теперь `ProductItem` получает `company.settlement`, поэтому:

```tsx
<Link
  href={`/${product.id}`}
  aria-label="Заказать паровой калорифер КПСк 4-11 с доставкой в город Омск"
>
  КПСк 4-11
</Link>
```

Для категории используется множественное число:

```text
Заказать паровые калориферы КПСк с доставкой в город Омск
```

### 4. `components/products/product-delivery-city-link.tsx`

Drop-in компонент для ячейки населённого пункта на товарной странице.

Текущий исходный файл товарной страницы в доступных файлах отсутствует,
поэтому его нельзя безопасно переписать целиком без риска затереть текущую
разметку. Компонент сделан независимым от структуры таблицы.

В файле товарной страницы добавьте:

```tsx
import { ProductDeliveryCityLink } from "@/components/products/product-delivery-city-link";
```

В той ячейке, где сейчас вручную рендерится `delivery.settlement.href`,
замените только содержимое ячейки на:

```tsx
<ProductDeliveryCityLink product={product} delivery={delivery} />
```

Для:

- `product.name = "Калорифер КПСк 4-11"` (или `"КПСк 4-11"`);
- `delivery.settlement.name = "Омск"`;

получится:

```html
<a
  href="/regions/omsk"
  aria-label="Опыт эксплуатации калориферов КПСк 4-11 на предприятиях города Омска"
>
  г. Омск
</a>
```

Если `delivery.settlement.href === null`, компонент оставляет обычный текст
без ссылки и без aria-label.

## Товарные формулировки

Региональная ссылка использует:

- КСк / КСК → водяной калорифер;
- КПСк / КПСК → паровой калорифер;
- ТВВ → водяной калорифер;
- КП → паровой калорифер;
- КПВС / КПВУ → водяной калорифер;
- КППС / КППУ → паровой калорифер;
- КФБ ... М → водяной калорифер;
- КФБ ... П → паровой калорифер;
- СФО → электрокалорифер;
- СФОЦ → отопительная установка;
- ШУК → шкаф управления;
- АО 2 / СТД-300 / АВО → отопительный агрегат;
- ТЭНы → оребренный ТЭН.

Для `kind: "category"` используется множественное число.
Для конкретной модели — единственное число.

На обратной ссылке товар → регион намеренно используется нейтральная
формулировка группы, например:

`Опыт эксплуатации калориферов КПСк 4-11 ...`

без повторения `паровых / водяных`, как в согласованном шаблоне.
